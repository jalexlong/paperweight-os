# PaperweightOS Theme Authoring Guide

## Overview

The theme system has two independent layers:

**Per-user theme** — seven files in `~/.config/`, switched live with
`paperweight-theme <name>`. No sudo required. Covers sway window borders,
waybar, swaync, gtklock, wofi, and foot.

**System surfaces** — gtkgreet (login screen), GRUB boot menu, and Plymouth
boot splash. Each has its own `sudo` helper. These are separate from the
per-user switcher; `paperweight-theme` calls them automatically if the user
is in the `sudo` group.

---

## Naming rules

- Lowercase ASCII only — no spaces, no accents, no special characters.
- The name is used verbatim as a filename component across all seven files and
  two directories. A typo or non-ASCII character (e.g. `frappé` instead of
  `frappe`) will silently break validation.
- `paperweight-theme` validates that all seven files exist before touching
  anything. A partial set of files will produce an error and leave the active
  theme unchanged.

---

## The 26 palette variables

All Catppuccin themes share the same 26 named colors. Each theme file uses
the same names — only the hex values change. The semantic groupings:

| Group | Variables |
|---|---|
| Accents | `rosewater` `flamingo` `pink` `mauve` `red` `maroon` `peach` `yellow` `green` `teal` `sky` `sapphire` `blue` `lavender` |
| Text | `text` `subtext1` `subtext0` |
| Overlays | `overlay2` `overlay1` `overlay0` |
| Surfaces | `surface2` `surface1` `surface0` |
| Base | `base` `mantle` `crust` |

For non-Catppuccin themes you can define any palette you like, but the sway
`client.*` color rules in `90-theme.conf` reference specific variable names
(`$lavender`, `$crust`, `$surface0`, `$surface1`, `$text`, `$red`). Those six
must always be defined in the sway theme file even if the palette doesn't use
the rest.

## Per-user theme files

All seven files live under `~/.config/` on the installed system. In the
packaging tree they live under:
`packaging/paperweight-skel/etc/skel/.config/`

### 1. `sway/themes/<name>.conf`

Defines color variables for sway using `set $varname #rrggbb`.

```
# My Theme — sway palette
set $rosewater  #hexhex
set $flamingo   #hexhex
# … all 26 variables …
set $base       #hexhex
set $mantle     #hexhex
set $crust      #hexhex
```

At minimum, define the six variables referenced in `90-theme.conf`:
`$lavender`, `$crust`, `$surface0`, `$surface1`, `$text`, `$red`.
Defining all 26 makes the theme available as a base for waybar/wofi CSS.

### 2. `waybar/themes/<name>-palette.css`

CSS equivalent of the sway palette using `@define-color`.

```css
@define-color rosewater #hexhex;
@define-color flamingo  #hexhex;
/* … all 26 variables … */
@define-color base      #hexhex;
@define-color mantle    #hexhex;
@define-color crust     #hexhex;
```

All 26 variables are required. `waybar/style.css` is generated by
`paperweight-theme` to import this file followed by the module styles file.

### 3. `waybar/themes/<name>-waybar.css`

Module styles for waybar, referencing the CSS variables from the palette file.

For Catppuccin variants: **copy `macchiato-waybar.css` verbatim.** All
Catppuccin variants use the same relative contrast ratios; only the palette
hex values change. The shared module CSS already references generic names
(`@base`, `@surface0`, `@blue`, etc.) that resolve from whichever palette
is active.

For non-Catppuccin themes: write module styles from scratch or adapt the
existing file. Waybar CSS classes to target:
`#workspaces`, `#workspaces button`, `#cpu`, `#memory`, `#clock`, `#battery`,
`#network`, `#pulseaudio`, `#custom-cava`, `#tray`.

### 4. `swaync/themes/<name>.css`

Self-contained CSS for the swaync notification center and control panel.
Uses **hardcoded hex values** (GTK4 CSS does not support `@define-color` in
the same way across swaync's widget paths). Copy an existing theme and
replace all hex color values.

Key selectors:
- `.notification-background` — toast card background
- `.notification .close-button` — dismiss button
- `.control-center` — slide-out panel background
- `.widget-title`, `.widget-dnd`, `.widget-mpris` — panel widgets
- `.urgency-low`, `.urgency-normal`, `.urgency-critical` — border colors

### 5. `gtklock/themes/<name>.css`

CSS for the gtklock screen locker. Uses hardcoded hex values. GTK4 CSS
restrictions apply: no `display: none`, no `max-height`, no unitless
`font-size: 0`. To hide elements use `opacity: 0` with `padding: 0; margin: 0`.

Key selectors: `window`, `#clock-label`, `#date-label`, `box#body`,
`entry`, `entry:focus`, `button`, `button:hover`, `button:active`.

### 6. `wofi/themes/<name>.css`

CSS for the wofi launcher. Starts with `@define-color` palette declarations
(same 26 names), then uses them in wofi-specific selectors.

```css
@define-color base #hexhex;
/* … palette … */

* { color: @text; font-family: "JetBrainsMono Nerd Font", monospace; }
window { background-color: @base; border: 1px solid @surface1; }
#input { background: @surface0; color: @text; border: 1px solid @surface1; }
#inner-box { background: @base; }
#outer-box { padding: 8px; }
#entry:selected { background: @surface1; }
#text:selected { color: @lavender; }
```

### 7. `foot/themes/<name>.ini`

Terminal color scheme. Uses **bare hex values without `#` prefix**.
The `background` value should be the theme's `crust` color (darkest base)
so the foot alpha layer blends correctly.

```ini
[colors]
background=181926
foreground=cad3f5
regular0=494d64   # black
regular1=ed8796   # red
regular2=a6da95   # green
regular3=eed49f   # yellow
regular4=8aadf4   # blue
regular5=f5bde6   # magenta
regular6=8bd5ca   # cyan
regular7=b8c0e0   # white
bright0=5b6078    # bright black
bright1=ed8796    # bright red
bright2=a6da95    # bright green
bright3=eed49f    # bright yellow
bright4=8aadf4    # bright blue
bright5=f5bde6    # bright magenta
bright6=8bd5ca    # bright cyan
bright7=a5adcb    # bright white
```

`foot/colors.ini` is the active theme file written by `paperweight-theme`.
`foot/foot.ini` includes it with `include=~/.config/foot/colors.ini`.

## Wallpaper (optional)

`paperweight-theme` resolves the wallpaper for a theme in this order:

1. `~/.config/paperweight-os/wallpapers/<name>` — user override file
   containing a single absolute path to an image.
2. `/usr/share/paperweight-os/wallpapers/<name>-wallpaper1.jpg` — package
   default artwork (shipped by `paperweight-wallpapers`).
3. `/usr/share/paperweight-os/wallpapers/<name>.png` — solid-color PNG
   fallback.

If none of these exist the desktop background is left at whatever sway last
set. The wallpaper path is written into
`~/.config/sway/config.d/91-wallpaper.conf` so it persists through
`swaymsg reload` and reboots.

To ship a default wallpaper for a new theme, add the image to:
`packaging/paperweight-wallpapers/usr/share/paperweight-os/wallpapers/`

## System surface themes

These are separate from the per-user switcher and require `sudo`. They live
in different packages and have their own variant files.

### gtkgreet (login screen)

**Package:** `paperweight-skel`
**File:** `/etc/greetd/themes/<name>.css`
**In packaging tree:** `packaging/paperweight-skel/etc/greetd/themes/<name>.css`
**Apply:** `sudo paperweight-set-greeter-theme <name>`

The gtkgreet CSS uses GTK4's `@define-color` for the headerbar color override
plus regular CSS selectors for the login form. See `macchiato.css` in
`etc/greetd/themes/` for the full pattern; the `headerbar_bg_color` named
color and the `headerbar { background-color }` rule are both required to
override the Adwaita headerbar.

`paperweight-theme` calls `paperweight-set-greeter-theme` automatically
when the user is in the `sudo` group. Non-sudo users can manually add the
CSS file to `/etc/greetd/themes/` and call the helper with `sudo`.

### GRUB boot menu

**Package:** `paperweight-grub`
**File:** `/usr/share/grub/themes/paperweight/<name>.txt`
**In packaging tree:** `packaging/paperweight-grub/usr/share/grub/themes/paperweight/<name>.txt`
**Apply:** `sudo paperweight-grub-theme <name>`

The GRUB theme files are color-override variants of a shared theme layout.
Copy an existing `.txt` variant and replace the color hex values. The theme
structure (font, image paths, layout) is shared; only the palette changes.

### Plymouth boot splash

**Package:** `paperweight-plymouth`
**File:** `/usr/share/plymouth/themes/paperweight/<name>.script`
**In packaging tree:** `packaging/paperweight-plymouth/usr/share/plymouth/themes/paperweight/<name>.script`
**Apply:** `sudo paperweight-plymouth-theme <name>`

Plymouth scripts define the boot animation and color palette in a custom
scripting language. Copy an existing `.script` variant and replace color
values. The three-dot animation logic is shared; colors are variables at
the top of the script.

Note: `paperweight-plymouth-theme` backs up the current initramfs before
rebuilding and restores it automatically if the rebuild produces invalid
output. See the script itself for details.

## Registering a new theme in the package

### Minimal path (per-user only, Catppuccin variant)

1. Create all seven files in the packaging tree:
   ```
   packaging/paperweight-skel/etc/skel/.config/sway/themes/<name>.conf
   packaging/paperweight-skel/etc/skel/.config/waybar/themes/<name>-palette.css
   packaging/paperweight-skel/etc/skel/.config/waybar/themes/<name>-waybar.css
   packaging/paperweight-skel/etc/skel/.config/swaync/themes/<name>.css
   packaging/paperweight-skel/etc/skel/.config/gtklock/themes/<name>.css
   packaging/paperweight-skel/etc/skel/.config/wofi/themes/<name>.css
   packaging/paperweight-skel/etc/skel/.config/foot/themes/<name>.ini
   ```
2. No changes to `debian/install` — the `themes/` directory globs pick up
   new files automatically.
3. Add a gtkgreet CSS at `packaging/paperweight-skel/etc/greetd/themes/<name>.css`.
4. Bump `paperweight-skel` version and add a changelog entry.
5. Optionally add a wallpaper to `paperweight-wallpapers` (bump that version too).

### Full path (new theme family, non-Catppuccin)

All of the above, plus:
- Add a GRUB variant `.txt` to `packaging/paperweight-grub/` (bump version).
- Add a Plymouth `.script` to `packaging/paperweight-plymouth/` (bump version).
- Update the `VARIANTS` case statement in both `paperweight-grub-theme` and
  `paperweight-plymouth-theme` helper scripts to accept the new name.

## Testing checklist

After creating all files, test in this order:

```sh
# Validate without applying (dry-run: paperweight-theme checks all files first)
paperweight-theme <name>    # should apply cleanly; check for notify-send error

# Verify each surface
swaymsg -t get_outputs      # check wallpaper path
pgrep -x waybar             # should be exactly 1
cat ~/.config/paperweight-os/active-theme   # should be <name>

# Verify persistence
swaymsg reload              # wallpaper should survive
cat ~/.config/sway/config.d/91-wallpaper.conf   # should show wallpaper path

# Check log for timing and any errors
tail ~/.local/share/paperweight-os/theme-switch.log

# Switch back to macchiato and back to confirm toggle works
paperweight-theme macchiato
paperweight-theme <name>

# System surfaces (if in sudo group)
sudo paperweight-set-greeter-theme <name>   # gtkgreet CSS applied
sudo paperweight-grub-theme <name>          # should print "GRUB theme set" or "already <name>"
sudo paperweight-plymouth-theme <name>      # backs up initramfs, rebuilds
ls -lh /boot/initrd.img-$(uname -r)*       # .bak should exist alongside the rebuilt one
```
